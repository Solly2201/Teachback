# Adversarial evaluation report

Generated by `python scripts/adversarial_audit.py`; raw per-case data in
`data/nlp/adversarial_audit.json`. Nothing in this set is used to tune a
threshold — it is an audit, not a calibration set.

## What it measures

Accuracy is not the point. Two outcomes are far more damaging than a
misclassification, and this audit is built to count them:

- **False credit** — an answer with no understanding in it is reported to the
  student as a demonstrated concept. They are told they know something they do
  not, and the gap never surfaces.
- **False accusation** — a correct answer, or simply an absent one, is named as
  a misconception or turned into a remediation task. The student is corrected
  for something they did not do.

Every case runs the real pipeline: `analyze_response` + `targeted_concept_check`
+ the conversation engine's own verdict + the recommender.

## Scope

**151 fixed cases — 139 answers and 12 relationship probes — across four
topics** (Strings in Python, Backpropagation, Hidden Markov Models, Overfitting
and Generalisation), covering the eight families:

| family | what it contains |
|---|---|
| A. clearly correct | textbook, paraphrase, informal, colloquial, very short, longer, student's own terminology, analogy, worked example, correct answer padded with irrelevant words |
| B. partially correct | right idea missing a fact, right fact without the meaning, right meaning wrong example, two concepts mixed, directionally right but vague |
| C. incorrect | plainly wrong, plausible but wrong, a neighbouring concept, a reversed relationship, self-contradictory |
| D. misconceptions | each teacher-authored misconception, polarity flips, one-instead-of-zero, right vocabulary with wrong meaning |
| E. no evidence | unrelated sentence, filler, the question echoed back, random nouns, technical-sounding noise |
| F. uncertainty | "I don't know", "not sure", "no idea", "I don't remember", blank |
| G. language variation | spelling mistakes, no punctuation, lowercase, slang, conversational, Indian-English, terse, rambling |
| H. adversarial | correct answer carrying another concept's words, wrong answer carrying many right words, correct answer sharing no reference phrase, concept named but nothing explained, a misconception followed by its own correction, negation, mixed right-and-wrong claims |

The seven invariants are asserted independently of any accuracy number: a
concept that never came up never becomes a remediation target and is never
worded as a mistake; high confidence with no evidence never claims
understanding; MCQ evidence never fabricates or erases TeachBack evidence;
`not_discussed` never becomes `misunderstood`; the summary never manufactures
evidence.

## Bugs this audit found, and the fixes

**1. Both similarity scores had a floor the answer never had to earn.**
Reference texts are stored as `"Name: explanation"`, so an *empty* answer
already scored 0.82 against the Hidden states references and 0.76 against
Slicing — above the 0.62 credit bar. The floors range ~0.54–0.82 depending on
how self-descriptive the concept name is, so one absolute threshold meant a
different thing for every concept. *"umm well you know how it is"* and *"is this
going to be in the test"* were both being reported as demonstrated concepts.

*Fix:* each score is measured against its own floor — the identical measurement
with the answer removed — and credit goes to the score the **answer** lifted
above it (`analyzer.NAME_ONLY_LIFT`). No threshold was changed. The required
lift was swept 0.00–0.10 on the calibration split and left at a bare "must beat
its floor", because a wider margin bought nothing the floor had not already
bought and cost real answers.

**2. The per-question check was never given the lecture's other concept names.**
The whole-response analysis always had them; the targeted check did not, so a
bare list of the topic's own headings ("gradient descent backpropagation loss
weights") counted as an explanation of whichever concept was under discussion.
*Fix:* `api/teachback.py` now passes `sibling_names`, matching what the analyzer
already did.

**3. A polarity flip scored closer to the concept than to its own taught
misconception.** *"The next state depends on everything that happened before
it"* is the Markov property inverted; it shares nearly every word with the
teacher's sentence, so the embedding put it at 0.91 against the concept and 0.80
against the misconception it restates. No similarity rule separates those.
*Fix:* a concept defined by an exclusion ("depends *only* on…, *not* on…") caps
credit for an answer asserting the totality it rules out. Deliberately narrow —
quantifiers like "each" are excluded, so *"each state emits an observation"*
does not trip it — and it only ever *withholds* credit, never accuses.

**4. Filler and bare verdict words satisfied the evidence gate.** *"Overfitting
is a big problem"* cleared the two-informative-words requirement on "big" and
"problem". *Fix:* those, and the interjections, joined the existing vacuous-term
set alongside "important" and "useful".

All four are covered by regression tests in `tests/test_safety_invariants.py`.

## What it cost

The fix is a real trade and both directions are measured.

| | labelled set (held-out) | student audit |
|---|---|---|
| strong-evidence **precision** | 0.767 → **0.829** | 0.787 → **0.792** |
| strong-evidence **recall** | 0.733 → 0.644 | 0.686 → 0.442 |
| evidence-level accuracy | 0.862 → 0.839 | 0.753 → **0.759** |
| false credit on no-evidence answers | — | 0.133 → **0.044** |

Evidence-level accuracy — which treats "demonstrated" and "partly shown" as the
same answer to *did this student show understanding?* — is essentially
unchanged. What moved is the split between them: a correct answer far from the
teacher's wording is now more often credited on the **follow-up** question
rather than the first. The student is never told they are wrong; the concept
simply is not settled in one turn. In the ten simulated sessions the strongest
students now demonstrate five of six concepts rather than six, and the ordering
between strong, middling and struggling students is unchanged.

Re-running the audit with the floor fix disabled isolates its contribution:
false credit **0.108 → 0.067**, with 11 further answers no longer reported as
demonstrated. Given the choice between one extra question for a student who
understands and a confident "you've got it" for a student who wrote *"is this
going to be in the test"*, the extra question is the right error.

## Remaining limitations

- **A confidently wrong answer built from the right vocabulary can still be
  credited.** All four residual false credits are this shape — *"characters are
  the variables that hold a string"*, *"regularization increases the size of the
  weights"*. Sentence embeddings measure *aboutness*, not truth, and the two
  guards that catch a false claim both need something to compare against: a
  teacher-authored misconception, or an explicit polarity marker in the
  concept's own description. An arbitrary false statement in fluent topic
  vocabulary has neither. Closing this needs entailment checking, which means a
  model TeachBack deliberately does not have.
- **Misconception recall is 0.636 by choice.** A wrong belief phrased with
  entirely different vocabulary from the stored claim is missed. Precision is
  1.000 and is the property that matters: the system must never accuse a correct
  answer. Missed misconceptions fall through to the normal probe flow.
- **Two relationship probes out of twelve are missed** — a correct colloquial
  statement of a connection read as "not discussed", and a reversed one read as
  demonstrated. Both are pre-existing and unchanged by this pass.
- **The set is hand-written, not real students.** It is adversarial by
  construction, which makes the false-credit rate a stress figure rather than an
  expected field rate. It says nothing about how often real students phrase
  things this way.
